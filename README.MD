# Cyber Owl Servo Module

Управление сервоприводами совы через Modbus RTU или I2C (PCA9685) с веб-интерфейсом и REST API.

## Обзор

Проект **Cyber Owl Servo Module** — это серверное приложение на FastAPI для управления сервоприводами роботизированной совы через протокол Modbus RTU или I2C (PCA9685). Приложение предоставляет:

- REST API для программного управления сервоприводами
- Веб-интерфейс для ручного управления
- Поддержку предустановленных поз ("Радость", "Сон", "Готовность")
- Мониторинг состояния подключения к Modbus-устройству
- Логирование и конфигурируемые настройки

## Архитектура

Проект организован по модульному принципу:

```
app/
├── config/           # Конфигурация приложения
├── core/             # Основная логика
│   ├── httpd.py      # FastAPI-сервер
│   ├── logger.py     # Система логирования
│   ├── routers/      # API-роутеры
│   └── low_level_controllers/
│       ├── servo_controller.py        # Низкоуровневое управление сервами
│       └── servo_controller_manager.py # Менеджер контроллера
├── content/          # Статические файлы (веб-интерфейс)
└── main.py           # Точка входа
```

### Ключевые компоненты

1. **`servo_controller.py`** — потокобезопасный контроллер сервоприводов (Modbus RTU), реализующий:
   - Подключение к Modbus-устройству через `pymodbus`
   - Автоматическое переподключение при потере связи
   - Очередь команд для асинхронной обработки
   - Поддержку 4 сервоприводов:
     - `HV` (Head Vertical) — вертикальное положение головы
     - `HH` (Head Horizontal) — горизонтальное положение головы
     - `LW` (Left Wing) — левое крыло
     - `RW` (Right Wing) — правое крыло

2. **`i2c_servo_controller.py`** — потокобезопасный контроллер сервоприводов (I2C PCA9685), реализующий:
   - Подключение к PCA9685 через шину I2C
   - Автоматическое переподключение при потере связи
   - Очередь команд для асинхронной обработки
   - Поддержку 4 сервоприводов с теми же ID, что и Modbus
   - Преобразование значений 0–100 в углы 0–180°

2. **`servo_controller_manager.py`** — синглтон-менеджер, обеспечивающий централизованное управление экземпляром контроллера.

3. **`servo_controller_manager.py`** — синглтон-менеджер, обеспечивающий централизованное управление экземпляром контроллера. Автоматически выбирает тип контроллера в зависимости от формата `SERVO_SERIAL_PORT`.

4. **`servo_router.py`** — API-роутер с эндпоинтами для управления сервами:
   - `POST /servo/happy` — радостная поза
   - `POST /servo/sleep` — поза сна
   - `POST /servo/ready` — поза готовности
   - `POST /servo/lw_sign` — махание левым крылом
   - `POST /servo/rw_sign` — махание правым крылом
   - `POST /servo/set_positions` — установка произвольных позиций
   - `GET /servo/stats` — статистика подключения

4. **`httpd.py`** — основной FastAPI-сервер с поддержкой жизненного цикла (lifespan), автоматической инициализации контроллера при старте и корректного завершения.

## Веб-интерфейс

Доступен по корневому пути `/`. Интерфейс позволяет:

- Управлять положением каждого сервопривода через слайдеры
- Выполнять предустановленные позы кнопками
- Отправлять комбинации позиций с задержкой
- Просматривать документацию API через Swagger (`/docs`) и ReDoc (`/redoc`)

Интерфейс реализован в виде статического HTML-файла `app/content/index.html`.

## Конфигурация

Настройки приложения задаются через переменные окружения (`.env` файл):

| Переменная | Описание | Обязательная | Значение по умолчанию |
|------------|---------|-------------|----------------------|
| `SERVO_PORT` | Порт сервера | Да | — |
| `SERVO_HOST` | Хост сервера | Да | — |
| `SERVO_LOG_LEVEL` | Уровень логирования | Да | — |
| `SERVO_DOC_ROOT` | Путь к статическим файлам | Нет | `./content` |
| `SERVO_SERIAL_PORT` | Порт подключения к контроллеру сервоприводов | Нет | `/dev/ttyUSB0` |
| `SERVO_LOGS_DIR` | Директория для логов | Нет | `None` |

## Выбор протокола: Modbus или I2C

Тип контроллера определяется префиксом переменной `SERVO_SERIAL_PORT`:

### Modbus RTU (по умолчанию)

Для Modbus укажите последовательный порт:

```env
SERVO_SERIAL_PORT=/dev/ttyUSB0
```

### I2C (PCA9685)

Для I2C укажите шину и адрес PCA9685 в формате `I2C:<bus>:<address>`:

```env
# Шина 7, адрес 0x40
SERVO_SERIAL_PORT=I2C:7:0x40

# Шина 5, адрес 0x41
SERVO_SERIAL_PORT=I2C:5:0x41

# Шина 7, адрес 0x40 (сокращённо)
SERVO_SERIAL_PORT=I2C:7

# Шина 7, адрес 0x40 (полные дефолты)
SERVO_SERIAL_PORT=I2C
```

**Формат:** `I2C:<bus>:<address>`
- `<bus>` — номер I2C-шины Jetson (3, 4, 5, 6, 7). По умолчанию: `7`
- `<address>` — адрес PCA9685 в шестнадцатеричном формате. По умолчанию: `0x40`

**Привязка сервоприводов к каналам PCA9685:**

| Сервопривод | ID | Канал PCA9685 | Описание |
|-------------|----|:---:|----------|
| `HV` | 0 | 3 | Голова вертикально |
| `HH` | 1 | 2 | Голова горизонтально |
| `LW` | 2 | 0 | Левое крыло |
| `RW` | 4 | 1 | Правое крыло |

**Диапазон пульса:** `min_pulse=500, max_pulse=2400` (подбирается под конкретные сервоприводы)

Пример `.env` файла (Modbus):
```
SERVO_HOST=0.0.0.0
SERVO_PORT=8001
SERVO_LOG_LEVEL=INFO
SERVO_SERIAL_PORT=/dev/ttyUSB0
SERVO_DOC_ROOT=./app/content
SERVO_LOGS_DIR=./logs
```

Пример `.env` файла (I2C, Jetson Orin NX, шина 7, PCA9685 по адресу 0x40):
```
SERVO_HOST=0.0.0.0
SERVO_PORT=8001
SERVO_LOG_LEVEL=INFO
SERVO_SERIAL_PORT=I2C:7:0x40
SERVO_DOC_ROOT=./app/content
SERVO_LOGS_DIR=./logs
```

## Зависимости

Основные зависимости:

- `fastapi` — веб-фреймворк
- `uvicorn` — ASGI-сервер
- `pymodbus` — работа с Modbus RTU
- `pyserial` — работа с последовательным портом
- `python-dotenv` — загрузка переменных окружения
- `pydantic` — валидация данных

### I2C-зависимости (только для Jetson/платформ с Blinka)

При использовании I2C-контроллера требуются:

```bash
pip install adafruit-blinka adafruit-circuitpython-pca9685 adafruit-circuitpython-motor
```

Эти библиотеки автоматически устанавливаются из `requirements.txt`.

**Примечание:** `adafruit-blinka` мапит `board.SCL`/`board.SDA` на GPIO Jetson через `jetson.gpio`.

## Запуск

### 1. Через Docker (рекомендуется)

Создайте `.env` файл с настройками, затем:

```bash
docker-compose up --build
```

### 2. Локально

```bash
# Установка зависимостей
python -m venv venv
source venv/bin/activate  # Linux/Mac
# или
venv\Scripts\activate     # Windows

pip install -r requirements.txt

# Запуск
python -m app.main
```

## Docker

Проект включает `Dockerfile` и `docker-compose.yml` для контейнеризации. Особенности:

После запуска сервера документация доступна по:

- Swagger UI: `http://<host>:<port>/docs`

## Безопасность и надёжность

- Контроллер работает в отдельном потоке
- Реализовано автоматическое переподключение к устройству с экспоненциальной задержкой
- Все команды проходят валидацию диапазона значений (0–100)
- Статистика подключения доступна через API
- Поддержка двух протоколов (Modbus RTU / I2C) без изменения API
